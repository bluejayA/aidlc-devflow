# Auto Mode 가이드

요구사항만 입력하면 설계부터 코드까지 자동으로 완성하는 초보자용 모드입니다.

---

## 목적

일반적인 devflow는 매 단계마다 사용자의 승인을 받으며 진행합니다. 이 방식은 숙련된 개발자에게 세밀한 제어를 제공하지만, 처음 사용하는 분에게는 진입장벽이 될 수 있습니다.

**Auto Mode**는 이 문제를 해결합니다:

- 사용자가 **"무엇을 만들고 싶은지"만** 알려주면
- Claude가 **설계, 코드 생성, 빌드/테스트를 자율적으로** 진행하고
- 각 단계마다 **멀티에이전트 리뷰**로 품질을 검증합니다

설계 결과를 한 번 확인한 후에는 최종 결과물까지 자동으로 진행됩니다.

---

## 특징

### 한 번의 확인, 나머지는 자동

| 구간 | 동작 |
|------|------|
| 요구사항 분석 → 설계 완료 | Claude가 자동으로 진행 |
| **설계 결과 확인** | **유일한 확인 지점** — 일상 언어로 요약 제시 |
| 코드 생성 → 빌드/테스트 → 완료 | Claude가 자동으로 진행 |

### 멀티에이전트 리뷰

사람 대신 5개 관점의 AI 리뷰어가 자동으로 설계와 코드를 검토합니다:

| 리뷰어 | 검토 관점 |
|--------|----------|
| Spec Reviewer | 요구사항 충족 여부 |
| Code Reviewer | 코드 품질과 설계 정합성 |
| Quality Reviewer | 가독성, 네이밍, 중복 |
| Security Reviewer | 보안 취약점 (OWASP Top 10) |
| Maintainability Reviewer | 장기 유지보수성 |

리뷰에서 문제가 발견되면 Claude가 자동으로 수정하고 다시 리뷰를 받습니다 (최대 3회).

### 전 과정 기록

Claude의 모든 자율 판단 — 복잡도 선언, 기술 스택 선택, 가정 처리 등 — 이 `auto-decision-log`에 기록됩니다. 나중에 "왜 이렇게 결정했지?"를 확인할 수 있습니다.

### 안전장치

| 장치 | 설명 |
|------|------|
| 고위험 가정 게이트 | 인증 방식, 결제 연동 등 중요한 자동 판단은 진행 전에 확인 |
| 글로벌 서킷 브레이커 | 자동 수정이 반복 실패하면 멈추고 사용자에게 알림 |
| devflow 전환 | 언제든 "단계별 모드"로 전환하여 직접 제어 가능 |
| 세션 복원 | 터미널을 닫아도 다시 시작하면 이어서 진행 제안 |

## 아키텍처

### 기존 devflow와의 관계

```
┌───────────────────────────────────────────┐
│             사용자 요청                      │
│                │                           │
│        ┌───────┴───────┐                   │
│        ▼               ▼                   │
│  aidlc-auto-mode  aidlc-using-devflow      │
│  (자동 모드)       (단계별 모드)              │
│        │               │                   │
│        └───────┬───────┘                   │
│                ▼                           │
│     동일한 stage skills 재활용               │
│  (requirements-analysis, code-generation,  │
│   build-and-test 등)                       │
└───────────────────────────────────────────┘
```

**핵심 설계 원칙:**

- **독립 파일**: `aidlc-auto-mode`는 단일 SKILL.md 파일. 기존 devflow는 한 줄도 수정하지 않음
- **재활용**: 기존 stage 스킬(요구사항 분석, 코드 생성 등)을 그대로 호출
- **호환**: devflow와 동일한 상태 파일(`devflow-state.md`, `session-summary.md`)을 사용하므로, 언제든 단계별 모드로 전환 가능
- **분리 가능**: auto-mode가 필요 없으면 디렉토리 하나를 삭제하면 끝

### 진행 흐름 상세

```
요구사항 입력
  │
  ▼
[자동] 프로젝트 환경 분석 → 규모 판단 → 요구사항 분석
  │    → (고위험 가정이 있으면 확인 요청)
  │    → 사용자 시나리오 → 성능/보안 기준
  │    → 구현 계획 → 시스템 설계
  │
  ▼
[자동] 5개 AI 리뷰어가 설계 검토
  │    → 문제 발견 시 자동 수정 + 재검토 (최대 3회)
  │
  ▼
[확인] 설계 결과를 일상 언어로 요약하여 제시  ← 유일한 확인 지점
  │    "만들려는 것: ..., 기술 스택: ..., 자동 결정 항목: ..."
  │    → 수정할 부분 선택 가능
  │
  ▼
[자동] 코드 생성 → 빌드 → 테스트
  │    → 테스트 실패 시 자동 수정 (최대 3회)
  │
  ▼
[자동] 4개 관점 코드 리뷰
  │    → 문제 발견 시 자동 수정 + 재검토 (최대 3회)
  │
  ▼
[완료] 결과물 + 실행 방법 안내
  │    "지금 실행해볼까요?"
  │
  ▼
"다음 작업도 auto 모드로 진행할까요?"
```

### 산출물

auto-mode가 생성하는 파일은 기존 devflow와 동일합니다:

```
devflow-docs/
├── inception/               # 설계 산출물
│   ├── requirements.md      # 요구사항 문서
│   ├── workflow-plan.md     # 구현 계획
│   └── ...
├── construction/            # 코드 산출물
├── devflow-state.md         # 현재 상태 (devflow 호환)
├── session-summary.md       # 세션 요약 (devflow 호환)
├── auto-decision-log-inception.md      # 설계 단계 판단 기록 (auto 전용)
└── auto-decision-log-construction.md   # 구현 단계 판단 기록 (auto 전용)
```

## 사용법

### 시작하기

```
"auto 모드로 TODO 앱 만들어줘"
```

다음 키워드 중 하나가 포함되면 auto-mode가 활성화됩니다:
- "auto 모드"
- "자동 모드"
- "auto mode"
- "알아서 만들어줘"

### 진행 중 보이는 것

auto-mode는 각 단계마다 진행 상황을 알려줍니다:

```
프로젝트 환경을 분석하고 있습니다...
프로젝트 규모를 판단하고 있습니다...
요구사항을 분석하고 있습니다...
구현 계획을 수립하고 있습니다...
설계를 검토하고 있습니다... (5개 관점)
```

### 설계 확인

설계가 완료되면 일상 언어로 요약된 결과를 보여줍니다:

```
## 설계가 완료되었습니다

만들려는 것: 할 일을 추가/삭제할 수 있는 TODO 웹앱
프로젝트 규모: 작은 프로젝트 (단일 서비스)
기술 스택: Next.js + SQLite

## 자동으로 결정한 항목 (검토해 주세요)
1. 데이터베이스 → SQLite (이유: 작은 프로젝트에 적합)
2. 인증 → 없음 (이유: 요구사항에 언급 없음)

A) 수정할 부분이 있습니다
   1. 기술 스택 변경
   2. 기타 (직접 입력)
B) 좋습니다, 코드 생성을 시작합니다
```

### 완료 후

```
프로젝트가 완성되었습니다!

생성된 파일: 12개
테스트: 8개 통과

→ 지금 바로 실행해볼까요?
A) 네, 실행 방법을 알려주세요
B) 나중에 실행하겠습니다

다음 작업도 auto 모드로 진행할까요?
```

### 문제가 생겼을 때

자동으로 해결할 수 없는 문제가 발생하면 멈추고 알려줍니다:

```
6단계 중 5단계까지 완료되었습니다.
테스트에서 확인이 필요한 부분이 있습니다: 로그인 검증 테스트 실패
A) 자세히 보기
B) 하나씩 확인하면서 진행하기 (단계별 모드)
```

### 단계별 모드(devflow)로 전환

auto-mode 진행 중 언제든 단계별 모드로 전환할 수 있습니다. auto-mode가 만든 설계와 상태 파일은 그대로 유지되므로, 중단된 지점부터 이어서 진행됩니다.

### 세션이 끊겼을 때

다시 "auto 모드"로 시작하면 이전 작업을 자동으로 감지합니다:

```
이전에 자동 모드로 진행하던 작업이 있습니다.
진행 상황: 4단계 중 3단계 완료
A) 이어서 진행하기
B) 처음부터 새로 시작하기
```

## 제한 사항

| 제한 | 이유 |
|------|------|
| **새 프로젝트(greenfield)만 지원** | 기존 코드가 있는 프로젝트는 코드베이스 이해가 필요하여 단계별 제어가 더 적합 |
| **매번 auto 모드 여부 확인** | 사용자가 익숙해지면 단계별 모드로 전환할 수 있도록 |
| **자동 수정 최대 3회** | 3회 실패는 Claude가 해결할 수 없는 문제를 의미 |

---

## Auto Mode vs 단계별 모드

| | Auto Mode | 단계별 모드 (devflow) |
|---|---|---|
| 대상 | 초보자, 빠른 프로토타이핑 | 숙련자, 세밀한 제어 |
| 사용자 개입 | 설계 확인 1회 | 매 단계 승인 |
| 리뷰 | 자동 (필수) | 선택적 |
| 적합한 프로젝트 | 새 프로젝트 (greenfield) | 모든 프로젝트 |
| 진행 속도 | 빠름 | 단계별 |
| 의사결정 기록 | 자동 (decision-log) | 간략 (audit.md) |
