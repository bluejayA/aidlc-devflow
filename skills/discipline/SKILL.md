# discipline

## 테스트 먼저

실패하는 테스트를 먼저 쓰고, **실패를 본 뒤** 통과할 최소 코드를 쓴다. 실패를 보지 않았으면 그 테스트가 맞는 걸 검증하는지 모른다. 코드가 먼저 나왔으면 테스트를 추가하는 게 아니라, 그 코드를 잠시 치우고 테스트가 실패하는지 본다.

- 테스트는 mock이 아니라 행위를 검증한다. 엣지·실패 경로도 하나씩.
- 던져 볼 스파이크, 생성 코드, 설정 파일은 예외 — 사용자에게 말하고 건너뛴다.
- 디버깅 중이면: 재현 → 원인 가설 하나 → 그것을 확인하는 테스트 → 수정. 추측 수정을 두 번 연속 하지 않는다.

## 완료라고 말하기 전

"됐습니다"의 근거는 이 메시지 안에서 돌린 명령의 출력이다.

1. 이 주장을 증명하는 명령은 무엇인가 (전체 테스트, 빌드, 린트)
2. 지금 돌린다 — 전체, 새로
3. 출력을 읽는다 — exit code, 실패 수, 경고
4. 출력이 주장과 맞으면 증거와 함께 말한다. 아니면 실제 상태를 말한다

| 주장 | 필요한 것 | 충분하지 않은 것 |
|------|----------|----------------|
| 테스트 통과 | 지금 돌린 전체 스위트 출력 | 아까 통과했다, 일부만 돌렸다 |
| 빌드 됨 | 빌드 명령 exit 0 | 린트만 통과 |
| 버그 고침 | 재현 테스트가 RED→GREEN | 코드를 바꿨다 |
| 회귀 없음 | 기존 테스트 전부 통과 | 바꾼 파일의 테스트만 |

커밋 전에 테스트를 돌리지 않았으면 `pretool-git` 훅이 커밋을 막는다. 그때는 돌리면 된다.
