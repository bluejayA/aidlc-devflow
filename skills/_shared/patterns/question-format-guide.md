# Question Format Guide

채팅 기반 질문의 품질 원칙. 게이트 구조(`gate-patterns.md`)는 선택지의 **틀**을 정의하고, 이 가이드는 선택지의 **내용 품질**을 정의한다.

> **적용 범위**: INCEPTION 스킬들의 사용자 질문, 오케스트레이터 게이트 선택지

---

## 1. 선택지 설계 원칙

### 개수 규칙

- **최소**: 의미 있는 옵션 2개 + "직접 입력"
- **최대**: 의미 있는 옵션 5개 + "직접 입력"
- 채우기용 옵션 금지 — 현실적으로 선택될 수 있는 것만 포함

### 품질 기준

- **상호 배타적**: 옵션 간 의미가 겹치지 않아야 한다
- **구체적**: "기타 방식" 같은 모호한 옵션 대신 실제 대안 제시
- **비개발자 친화적**: 전문 용어에는 한 줄 설명 병기

### 좋은 예

```
인증 방식을 선택해주세요:
A) 이메일 + 비밀번호
B) 소셜 로그인 (Google, GitHub 등)
C) SSO — 회사 계정으로 한 번에 로그인하는 방식
D) 직접 입력
```

- 각 옵션이 명확히 다른 인증 메커니즘
- SSO에 비개발자용 설명 병기
- "직접 입력"으로 예상 밖 답변 수용

### 나쁜 예

```
인증 방식을 선택해주세요:
A) 이메일 로그인
B) 비밀번호 로그인        ← A와 사실상 동일
C) 보안 로그인            ← 의미 모호
D) 기타 로그인 방식       ← "직접 입력"과 중복
E) 직접 입력
```

- A/B 중복, C 모호, D가 E와 기능 중복 → 슬롯 채우기의 전형

---

## 2. 자유 입력 보장

### "직접 입력" 옵션 필수

모든 선택형 질문의 마지막에 자유 입력 옵션을 반드시 포함한다.

```
D) 직접 입력
```

### 사용자 주도 답변 수용

사용자가 선택지를 무시하고 상세 답변을 제공하면, **그대로 반영**한다. 선택지로 되돌리려 하지 않는다.

**예시: 고급 개발자의 자유 답변**

```
사용자: "Rust + Axum + SQLx로 할게. DB는 PostgreSQL, 배포는 Fly.io"
```

→ 추가 기술 스택 질문 없이 즉시 수용. 이미 충분한 정보를 담고 있으므로 관련 질문을 건너뛴다.

**예시: 비개발자의 자유 답변**

```
사용자: "로그인은 구글로 하고 싶어요"
```

→ "B) 소셜 로그인"으로 내부 매핑하되, 구글 특정 요구사항으로 기록.

---

## 3. 모순 감지 + 보충 질문

### 감지 시점

이전 답변과 현재 답변 사이에 불일치가 있을 때, **즉시** 확인한다. 다음 단계로 넘어가지 않는다.

### 감지 패턴

| 모순 유형 | 예시 |
|-----------|------|
| **범위 불일치** | "버그 수정"이라 했는데 "전체 아키텍처 변경" 선택 |
| **리스크 불일치** | "낮은 리스크"라 했는데 "브레이킹 체인지 있음" 선택 |
| **타임라인 불일치** | "빠른 수정"이라 했는데 "다수 서브시스템 영향" 선택 |
| **기술 불일치** | "프론트엔드만"이라 했는데 "DB 스키마 변경 필요" 선택 |

### 보충 질문 형식

모순을 발견하면 **판단하지 않고 질문으로 확인**한다:

```
앞서 "빠른 버그 수정"으로 분류하셨는데, 방금 "다수 서브시스템에 영향"을 선택하셨습니다.
확인이 필요합니다:

A) 실제로는 여러 곳에 걸친 버그라 범위가 큽니다 → 분류를 수정합니다
B) 버그 자체는 작지만, 수정이 여러 파일에 걸칩니다 → 분류는 유지합니다
C) 직접 설명
```

### 규칙

- 모순이 해소될 때까지 다음 단계 진행 금지
- 보충 질문도 동일한 선택지 설계 원칙(2~5개 + 직접 입력) 적용
- 보충은 최대 1회 — 2회 이상 모순이면 해당 영역 전체를 다시 질문

## 4. 수준 적응

### 판단 기준

첫 1~2개 질문에 대한 답변 **스타일**로 사용자 수준을 판단한다:

| 시그널 | 판단 |
|--------|------|
| 선택지 알파벳으로 답변 (예: "A") | 가이드 모드 유지 |
| 짧은 자유 답변 (예: "Next.js로 할게") | 전문가 모드 전환 고려 |
| 상세 기술 스택 일괄 지정 | 전문가 모드 즉시 전환 |
| 질문의 의미를 되묻는 경우 | 가이드 모드 + 설명 보강 |

### 가이드 모드 (비개발자 / 초보)

- 질문을 **하나씩** 제시
- 모든 선택지에 **한 줄 설명** 병기
- 전문 용어 사용 최소화
- 예시를 포함하여 이해 돕기

```
배포 환경을 선택해주세요:

A) 클라우드 서버 — AWS, GCP 같은 원격 서버에 올리는 방식
B) 자체 서버 — 직접 관리하는 물리 서버에 설치
C) 서버리스 — 서버 관리 없이 코드만 올리면 자동 실행되는 방식
D) 잘 모르겠어요 — 추천해드릴게요
E) 직접 입력
```

### 전문가 모드 (고급 개발자)

- **다중 질문 한 번에** 제시 (관련 질문 묶음)
- 설명 생략, 핵심만
- 이미 답변한 영역은 **자동 스킵**
- "한꺼번에 알려주셔도 됩니다" 안내

```
남은 확인 사항:
1. 테스트 전략 (unit/integration/e2e 비율)
2. CI/CD 파이프라인 선호
3. 모니터링/로깅 스택

한꺼번에 알려주셔도, 하나씩 진행해도 됩니다.
```

### 모드 전환

- 언제든 사용자 답변 스타일 변화에 따라 모드 재조정 가능
- 모드 전환은 암묵적 — 사용자에게 "전문가 모드로 전환합니다" 같은 알림 불필요
